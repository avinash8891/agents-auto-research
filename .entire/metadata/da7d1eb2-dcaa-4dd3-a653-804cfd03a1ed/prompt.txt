 1. Process control — best practice for your case

  Outcome-only, with structured output requirements that force the right process.

  The trick: don't tell the agent how to think. Instead, require its output to contain fields it can only fill
  by doing the right work.

  Examples:
  - ❌ Prompt: "Call list_past_theses first."
  - ✅ Output schema requires: "relation_to_prior_theses": [{"thesis_id": "...", "why_different": "..."}] —
  agent must call the tool to fill this.
  - ❌ Prompt: "Compare 2-3 candidates before picking one."
  - ✅ Output schema requires: "alternatives_considered": [{...}, {...}] with at least 2 entries.
  - ❌ Prompt: "Anchor on baseline."
  - ✅ Output schema requires: "baseline_comparison": {metric: ..., baseline_value: ..., latest_value: ...,
  delta: ...}.

  Why this is best practice: modern models are trained to reason and use tools. Heavy process prescription
  ("step 1: do X, step 2: do Y") fights the model. Output schemas push the same constraints to the boundary
  where they can actually be checked. did you ipmleknt this  here

  Empirical findings from 11 jobs / 94 rounds / 102 thesis attempts

  Outcome distribution

  - 27 theses selected for execution
  - 15 of 84 non-baseline experiments accepted (18%)
  - Only 2 got verdict_status='accepted'
  - 70 of 97 experiments not accepted by metric comparison

  Validator rejections (16 total)

  12 of 16 (75%) are 100% Jaccard overlap on sentinel metadata keys — requires_engine_change,
  requires_new_config_keys, new_config_keys_needed. These aren't real config keys, they're flags. Two
  completely different theses both setting requires_engine_change=true get falsely flagged as duplicates.

  This is a validator bug, not a thesis quality signal. thesis_validator.py:48 only ignores
  requires_engine_change; the agent uses three more variant names that aren't ignored.

  The remaining 4 rejections are legitimate (real config-key overlap, hypothesis-config misalignment, bad path
  construction).

  The big finding — theme fixation

  51 of 102 theses (50%) are variations on the opening session. Job 20 alone has 45 rounds of mostly
  opening-window and stop-distance variants:

  cap_wide_alert_candle_stop_distance_pct
  min_stop_distance_floor_to_reduce_microstructure_noise_stops
  stop_distance_quintile_cap_to_avoid_wide_stop_adverse_selection
  max_stop_distance_pct_cap_to_exclude_range_expansion_alert_candles
  min_stop_distance_pct_floor_to_avoid_micro_noise_stopouts
  tighten_risk_structure_via_min_stop_distance_pct_floor
  widen_initial_stop_via_max_stop_distance_pct_cap_removal       ← opposite direction of above

  Notice two patterns the validator misses entirely:

  1. Theme clustering — the agent re-clothes the same mechanism with different config keys. Jaccard finds
  nothing because the keys are technically different.
  2. Direction whipsawing — when one direction of a lever fails, the agent tries the opposite direction without
   acknowledging the lever may not be predictive at all.

  Disconfirmer reality

  - Zero of 27 selected theses contain falsification language in the hypothesis prose.
  - BUT the schema has a disqualifiers field that is populated (~2 entries per thesis on average).
  - However, every disqualifier I inspected is a metric threshold ("PF doesn't improve by 5%"), not a mechanism
   falsifier ("if up-drive mornings are NOT a bad regime in the data"). These are pass/fail criteria, not
  Popperian disconfirmers.

  Other observed failures

  - 56 of 94 rounds end in outcome='needs_code' — agent proposes code-required theses that never get built. Job
   20 has 31, job 26 has 20.
  - One rejection example shows alignment score 0.00 making it as far as validation — alignment scoring is
  diagnostic-only and not a gate.
  - Path-construction violation: agent built runtime/jobs/job-25/experiments/.../runtime_config.json for
  base_config_path. Validator caught it but only because of a hard prefix check; doesn't prevent the agent from
   trying again.

  B. NEW rules to ADD — codify the patterns the validator misses

  B1. Theme-cluster fixation detector.

  def check_theme_cluster_fixation(thesis, prior_theses_in_job, threshold=4, window=7):
      """Reject if 4+ of last 7 theses (including this one) share keywords."""
      keywords_now = extract_theme_keywords(thesis.thesis_id, thesis.hypothesis)
      recent = prior_theses_in_job[-(window-1):]
      overlap_count = 1  # this thesis
      for prior in recent:
          prior_kw = extract_theme_keywords(prior.thesis_id, prior.hypothesis)
          if len(keywords_now & prior_kw) >= 1:
              overlap_count += 1
      if overlap_count >= threshold:
          raise ThesisValidationError(
              f"Theme-cluster fixation: {overlap_count}/{window} recent theses share "
              f"keywords with this thesis ({keywords_now}). Propose from a different "
              f"cluster, or explicitly justify why this iteration tests a materially "
              f"new mechanism in `relation_to_prior`."
          )

  Keyword extraction: simple noun-phrase tokenization on thesis_id plus a small EMA-domain stoplist.

  B2. Direction-flip whipsaw detector.

  def check_direction_whipsaw(thesis, prior_theses):
      """Reject if a prior thesis tuned the same conceptual lever in the opposite direction

      lever_words = {"tighten", "widen", "increase", "decrease", "raise", "lower",

      ...

  B3. needs_code starvation rule.

  def check_code_required_starvation(thesis, prior_theses, max_consecutive=3):
      """Reject if 3+ consecutive prior theses required code changes and none ran.
      Forces a no-code thesis to be proposed."""

  Prevents the conductor from queueing infinite engine-change requests.

  B4. Promote hypothesis-config alignment to a hard gate.

  The score is already computed in check_hypothesis_alignment. Currently informational. Reject below 0.4
  (calibrate from data — score=0.00 cases are clearly bad; need to see distribution to set the right
  threshold).

  B5. Require ≥1 mechanism-falsification disqualifier.

  Schema-level: at least one disqualifier must reference observable evidence patterns (not metric thresholds).
  Heuristic: reject if every disqualifier's condition matches the regex
  (profit_factor|trade_count|expectancy|sharpe|drawdown).*\b(by|than)\b.*\d+. At least one must be
  qualitatively different.

  C. New schema fields — force the right reasoning

  C1. mechanism_falsification (required, string, ≥80 chars):
  "What observable pattern in the data would prove the mechanism wrong, independent of whether the backtest
  improves metrics?"

  This is the disconfirmer the user kept asking for, separate from metric disqualifiers.

  C2. theme_keywords (required, list, 2-3 entries):
  Agent's own categorization of what cluster this thesis belongs to. Used by B1.

  C3. prior_lever_outcomes (required when applicable):
  If a config key concept overlaps with prior work, must cite the prior thesis ID and one-sentence outcome.
