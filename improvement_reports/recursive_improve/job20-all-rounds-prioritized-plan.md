# Prioritized Improvement Plan

Generated by: recursive-improve Stage 5, report-only

## Summary

The largest quality gap is hidden success inflation: 55/55 traces are marked
successful, but strict clean success is 27/55. The largest operational gaps are
tool-error frequency, repeated missing path/timeouts, and p90 token/duration outliers.

Current-source caveat: some fixes appear partially addressed already, especially
market-data manifest guidance in `research_subagents.py` and tests around no raw-data
probing. The traces still justify keeping these as monitored fixes because the trace
set itself contains the failures.

## Fix Details

### 1. Require final assistant response and strict outcome labels

Type: code_fix.

Recommendation: update the trace adapter/evaluator path that writes adapted JSON so
`success=True` requires a terminal assistant response and, for clean success, no
unexpected tool-result errors. The likely ownership is the trace adaptation/eval layer
near `eval_harness.py`, `trace_improvement_report.py`, or the trace exporter that
produced these JSON files.

Evidence:

- `agents-R-ema-job-20-round-9-20260506-025932.json`: messages 0-1 only, no final.
- `agents-R-ema-job-20-round-15-20260506-094835.json`: messages 0-1 only, no final.
- `agents-R-ema-job-20-round-27-20260506-144345.json`: no final assistant response.

Risk: Low. It changes labeling, not research behavior.

Expected impact:

- `clean_success_rate`: up in future by preventing incomplete traces from being counted
  as clean; current truthful baseline becomes 49.1% instead of misleading 100%.
- `duration_outlier`: neutral.
- `error_rate`: short-term visibility may rise; long-term down as failures block acceptance.
- `recovery_rate`: becomes meaningful because denominator excludes incomplete traces.
- `token_usage`: neutral.

### 2. Add bounded failure/early-stop rules for tools

Type: prompt_fix.

Recommendation: add conductor/analyst instructions: after two failed `run_python` calls,
one timeout, or two missing-path `read_file` calls for the same hypothesis, stop probing,
state the unavailable data explicitly, and either answer from existing artifacts or propose
a code/schema prerequisite.

Evidence:

- Round 21 has five timeout messages and 10 tool-error events before final msg 73.
- Round 32 has 56 tool calls and repeated pandas tracebacks before final msg 135.
- Round 45 has a missing source path at msg 39 and timeout at msg 42, with 2,001,583 tokens.

Risk: Low. It limits currently failing behavior.

Expected impact:

- `clean_success_rate`: up by reducing noisy recoveries.
- `duration_outlier`: down, targeting 6/55 p90 outliers.
- `error_rate`: down, targeting 25/55 tool-error traces.
- `recovery_rate`: maintain; recover earlier with caveats.
- `token_usage`: down, targeting 6/55 p90 token outliers.

### 3. Enforce exact artifact and market-data manifests

Type: code_fix.

Recommendation: keep and harden the current manifest approach in `research_subagents.py`.
The analyst should receive exact `runtime_config`, `universe_path`, and OHLCV parquet
paths when available; tools should refuse recursive path probes or guessed repo-local
data directories when the manifest is unresolved.

Evidence:

- Round 17 msg 20 reports missing AAPL/AMZN/GOOGL/META/MSFT/NVDA/SPY/TSLA bars.
- Round 20 msg 30 reports missing `/root/autoresearch-2026-05-02/data`.
- Round 35 msg 44 raises `Fallback data root missing`.
- Current tests already assert manifest/no-probing behavior, so this may be partially
  handled and should be verified against fresh traces.

Risk: Medium. It modifies tool affordances and may block exploratory recovery paths.
Mitigation: allow exact manifest paths and artifact-local files; block only guessed
recursive paths.

Expected impact:

- `clean_success_rate`: up.
- `duration_outlier`: down.
- `error_rate`: down, especially missing-data errors in 17/55 traces.
- `recovery_rate`: maintain with clearer caveats.
- `token_usage`: down.

### 4. Extend strategy event schema for alert-candle and timing features

Type: code_fix.

Recommendation: log fields required by recurring hypotheses in the strategy/event
pipeline, likely near `strategies/ema/signals.py`, `strategies/ema/strategy.py`, and
`strategy_event_logger.py`: alert candle timestamp, alert high/low/open/close, range,
body-to-range, close location, entry minutes since open, and join keys from executed
trades to accepted signals.

Evidence:

- Round 35 msg 53: cannot validate range expansion because alert-candle OHLCV could
  not be reconstructed.
- Round 41 msg 47: cannot test activity-regime hypotheses because event artifacts lack
  volume/range/ATR features; msg 51 records `entry_minutes_since_open` missing.
- Round 47 msg 61: 0/2,569 executed shorts can be joined to alert-candle OHLC.

Risk: Medium. It changes artifact schema and downstream consumers.
Mitigation: add fields compatibly and keep old columns.

Expected impact:

- `clean_success_rate`: up for schema-dependent research.
- `duration_outlier`: down by avoiding reconstruction attempts.
- `error_rate`: down, especially `cannot validate` and failed join attempts.
- `recovery_rate`: maintain; fewer recoveries needed.
- `token_usage`: down.
