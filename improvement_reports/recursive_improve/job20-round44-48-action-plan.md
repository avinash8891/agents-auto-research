## Fix Details

### P1 - Deterministic Source Path Resolver

**Type:** code_fix

**Recommendation:** In `research_subagents.py`, pass exact strategy source paths into the analyst prompt based on the strategy family and repository root. Prefer a structured map such as `ema -> strategies/ema/signals.py, strategies/ema/exits.py, strategies/ema/strategy.py`. If the analyst `read_file` tool receives a repo-relative path, resolve it against the repo root before failing.

**Evidence:** Round 45 messages 38-46 show `../strategy.py` failure, recursive search timeout, and eventual discovery of `strategies/ema/strategy.py`.

**Risk:** Low. It adds deterministic context already implied by the conductor prompt.

**Metric impact:** `duration_outlier` down, `error_rate` down, `token_usage` down, `clean_success_rate` up.

### P2 - Incomplete-run Finalization Guard

**Type:** code_fix

**Recommendation:** In the trace adapter/run finalizer, classify any trace ending in `kind=tool_call` without a matching result or final assistant response as incomplete. Either continue the run to final response or export `success=false` with an explicit incomplete reason.

**Evidence:** Round 44 final message 43 is `tool=run_python`, `kind=tool_call`; top-level `success=true`; no conductor final JSON.

**Risk:** Low. It may lower reported success initially, but it improves metric truthfulness.

**Metric impact:** `clean_success_rate` becomes trustworthy; future `recovery_rate` improves when incomplete sessions are retried.

### P3 - Schema Pre-flight and Stop Rule

**Type:** prompt_fix

**Recommendation:** Add this analyst instruction near the top of the analyst prompt:

```text
Before computing a schema-dependent metric, list the exact required fields and join keys. Check their presence and expected non-null coverage on a small sample. If a required key is absent or coverage is zero after one validated join attempt, stop analysis for that hypothesis, report it as unmeasurable, and recommend the minimal instrumentation change. Do not continue with alternate timestamp guesses unless the prompt explicitly provides that mapping.
```

**Evidence:** Round 47 messages 50, 56, 58, and 60 show repeated failures before the missing alert-candle key conclusion.

**Risk:** Low. It changes behavior only after a pre-flight failure.

**Metric impact:** `error_rate` down, `duration_outlier` down, `token_usage` down, `recovery_rate` up.

### P4 - Add Alert-candle Provenance

**Type:** code_fix

**Recommendation:** Extend `StrategyEventLogger` and EMA logging calls to include `alert_bar_idx` and `alert_timestamp` for raw setups, accepted signals, rejected signals, order rejections, and executed trades where available. `strategies/ema/signals.py` already computes `alert_bar_idx`; propagate it through `strategies/ema/strategy.py`, `strategies/ema/exits.py`, and `strategy_event_logger.py`.

**Evidence:** Round 47 message 60 says 0/2569 executed shorts can be joined to alert-candle OHLC. Source inspection confirms `EMASignals.alert_bar_idx` exists but the event logger does not export it.

**Risk:** Medium. It changes event schema; mitigate by adding backward-compatible nullable columns and tests for old consumers.

**Metric impact:** `clean_success_rate` up indirectly, `error_rate` down, `token_usage` down, `recovery_rate` up.

### P5 - Bound Exploratory Filesystem Work

**Type:** process_fix

**Recommendation:** Add an analyst operating rule: no recursive filesystem discovery from artifact directories; allowed path discovery is one bounded repo-root lookup or the deterministic source map from P1. Enforce a one-attempt budget for path recovery before returning a missing-path diagnosis.

**Evidence:** Round 45 message 41 recursively searched with `**/strategy.py` and timed out.

**Risk:** Low. P1 should make this rarely needed.

**Metric impact:** `duration_outlier` down, `token_usage` down, `error_rate` down.

### P6 - Regression Checks for Good Behavior

**Type:** prompt_fix

**Recommendation:** Add two trace-level regression expectations:

```text
When analyst evidence shows a parameter is not a real lever, propose a different mechanism or stop; do not retune that parameter.
When a mechanism requires engine support, set requires_code_change=true and do not force a config-only delta.
```

**Evidence:** Round 46 messages 42 and 47 show correct rejection of `max_hold_bars`; round 48 message 53 correctly classifies two-stage exits as engine work.

**Risk:** Low.

**Metric impact:** Maintains `clean_success_rate`; slight indirect improvement to `recovery_rate` on unsupported-mechanism tasks.
